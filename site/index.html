dsh-bridge · Python capability bridge

Turn your Python into a native
deepseek-harness plugin.

Capability conversion, not reimplementation. Python stays Python — the harness sees a native plugin. Decorate a module, generate a TypeScript bridge, wire it in cordis.yml. No rewriting. No Pyodide. No FFI.

★ The biggest highlight
Zero changes to your Python business code.

Every decorator returns the original callable unchanged. When no bridge is attached, your code runs unmodified — same source, same semantics, just declared capabilities. The bridge is declarative metadata, not a code rewrite. 

# src/my_ml/provider.py — your existing Python, lightly annotated
from dataclasses import dataclass
from dsh_bridge import provide_method, service, tool, on

@service(name="ml")
@dataclass
class MLProvider:
    model_path: str
    @provide_method(timeout_ms=10_000)
    def embed(self, texts: list[str]) -> list[list[float]]:
        return [[0.0] * 768 for _ in texts]

@tool(name="shout", description="Upper-case a string.",
      parameters={"text": {"type": "string"}})
def shout(text: str) -> dict:
    return {"text": text.upper()}

@on("session/event", mode="emit")
def audit(event: str, payload: dict) -> None:
    ...

# cordis.yml — wire it in
- id: ml
  name: '@my-org/python-bridge-ml'
  config:
    pythonBin: python
    module: my_ml.provider
    className: MLProvider
    sandbox: workspace-write
    modelPath: /opt/models/embeddings.npy

Generate step in between: pnpm dsh-bridge-codegen src/my_ml/provider.py --out packages/@my-org/python-bridge-ml --name @my-org/python-bridge-ml 

# One command: codegen → build → assemble → smoke → patch
scripts/install-python-plugin.py \
  --source     path/to/bridge.py \
  --name       '@my-org/sample-bridge' \
  --module     sample_dsh.bridge \
  --python-src path/to/my-python/src \
  --config-json '{"boardId": "my-board"}'

Steps are decoupled — run any subset via --steps codegen,build,assemble,smoke,patch. --dry-run prints the patch without writing; --uninstall reverses it. Env overrides: DSH_TSC, DSH_NODE, DSH_MONOREPO, DSH_INSTALL.

Why this exists

dsh's plugin surface is TypeScript-only.

deepseek-harness plugins are TS packages that mount via Cordis (ctx.<name> services, ctx.tools.register(...), ctx.on(...)). The richest capability libraries — sklearn, PyTorch, NumPy — aren't.

Your Python is the capability.

A capability that took you months to tune shouldn't be re-validated in another language. dsh-bridge lets the algorithms, libraries, and state stay in Python; the harness sees a native plugin.

No reimplementation. No Pyodide. No FFI.

The bridge spawns a long-lived Python child process and forwards decorated methods over NDJSON JSON-RPC 2.0 on stdio. pip install works as-is; crashes are isolated to the child.
