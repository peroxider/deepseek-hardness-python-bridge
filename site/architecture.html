Architecture

How a Python module becomes a native dsh plugin.

No FFI, no in-process CPython, no shared memory. The bridge compiles your decorated Python into a TypeScript plugin that mounts like any other, then talks to a long-lived Python child process over NDJSON JSON-RPC 2.0 on stdio.

The data flow

Three things worth knowing

Why a subprocess, not Pyodide / pyo3

No CPython invasion. Whatever you can pip install works as-is — no recompile, no adapter layer, no compatibility matrix.

Crash isolation. A bad import, a segfault, an OOM — all confined to the child. The harness keeps running; the bridge has a teardown ladder (worker-exit, reconnect, env scrub).

Clear message boundary. Method call = message. No shared memory, no GIL entanglement. The protocol is JSON-RPC, so every cross-boundary interaction is auditable and replayable.

What flows on stdio

One JSON object per line (NDJSON framing). Each line is a JSON-RPC 2.0 request, response, or notification — correlated by id for call/response, fire-and-forget for @on listeners.

Arguments and return values are inferred from PEP 484 type hints (see Decorators) and serialized as plain JSON. Python dataclass returns must be asdict()'d first — anything that isn't JSON-roundtrip safe will fail the call with a -32603 / exception.

Where the bridge ends and dsh begins

The generated TS plugin is a real Cordis plugin. It receives the same sandboxing, env scrub, approval flow, session log, and persistence as a hand-written one — the bridge does not invent a parallel runtime.

Method calls, tool calls, and event emissions go through the same Cordis surface either side would. The Python process is just where the methods happen to execute.

What this bridge explicitly is not

  • Not an in-process CPython embedder. No Pyodide, no pyo3. The runtime stays in a separate process you can ps and signal like any other.
  • Not a Python reimplementation of Cordis. Python modules attach to dsh's existing Cordis context — they don't replace it.
  • Not bidirectional shared-memory state. All cross-boundary interaction is message-passing. If you need shared state, design it as a service with explicit methods.
  • Not a replacement for Code Mode's planned Python backend. Complementary, not competing — Code Mode's Python plans and the bridge target different integration points.
