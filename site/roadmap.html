Roadmap

Shipped, in progress, and next.

A flat list of what's in your hands today, what's actively being built, and what's queued — plus the explicit non-goals so you don't have to ask twice.

shipped

Already in your hands today.

  • Four emitting decorators — @service, @provide_method, @tool, @on.
  • Four-tier verification — 43 pytest, 55+ offline E2E assertions, REAL-composition through the genuine Cordis Loader, strict tsc -b zero errors.
  • One-command installer — scripts/install-python-plugin.py running codegen → build → assemble → smoke → patch.
  • Agent-friendly skill — skill/dsh-python-plugin/SKILL.md for AI coding agents driving the whole conversion.
  • Bilingual docs — Human Engineer Guide and Agent-friendly Guide, both EN and ZH.
  • Self-contained plugin packaging — the generated TS plus bundled python-src drops into any dsh install without external Python dependencies.

in progress

Being worked on now.

  • Emit @capability / @method — wire capability-seam replacements so a Python class can stand in for ctx.fs, ctx.shell, ctx.subprocess, etc.
  • Emit @guard / @restrict_tools — full tool-policy hooks (allow / deny lists, guard callbacks) round-tripping through JSON-RPC.
  • Emit @system_prompt_section — contribution to the agent's system prompt with explicit ordering.
  • Parser generalization — accept @dsh_bridge.service(...) qualified calls and from dsh_bridge import service as svc import aliases.

next

Queued after the above.

  • Non-dataclass __init__ introspection — accept services whose constructor takes regular def __init__(self, foo, bar) arguments, not just @dataclass.
  • Multiple @service per module — today only the first @service class is emitted. Lift that restriction so a single module can publish several services at once.
  • Standalone-vitest path — get the vitest suites under packages/bridge/*/tests/ running in the standalone repo (not just inside the monorepo).
  • Open a PR into deepseek-ai/deepseek-harness — turn the verified monorepo working-tree changes into a real upstream PR.

What we'll never do (so you don't ask twice)

Some design decisions were deliberate. Listed here so a feature request that would walk them back gets a quick, polite no.

No in-process CPython.

No Pyodide, no pyo3. The bridge's value depends on pip install-as-is working without recompilation or adapter layers.

No Python Cordis.

Python modules attach to dsh's existing Cordis context. We are not reimplementing Cordis on the Python side.

No shared-memory state.

All cross-boundary interaction is message-passing over JSON-RPC. If you want shared state, model it as a service with explicit methods.

No Code Mode replacement.

Complementary to Code Mode's planned Python backend. Different integration points; we don't compete.

Influence the roadmap

The fastest way to move something into "next" is a concrete use case. Open an issue, link your Python module, and describe the capability surface you want to expose — almost everything above started as a single issue.
